Tektronix TBS1072B-EDU

Drive the oscilloscope from your browser over WebUSB, and save what it measures.

Not connected
This browser cannot talk to the instrument. The WebUSB API is required, and is available in desktop Chrome and Edge (and Chromium derivatives). Firefox and Safari do not implement it, and neither do browsers on iOS. You can still explore the controls below — nothing will be sent to any hardware.
WebUSB needs a secure page. Open this page over https:// or on localhost.
First time on this computer? Windows needs the WinUSB driver bound once before any browser can see the scope. ChromeOS, macOS and Linux need little or nothing. On every system the scope's rear port must be set to Utility → Options → USB Device Port → Computer.

Waveform

Every point here came off the instrument: 2500 samples per channel, scaled by the preamble captured with them. The graticule matches the scope's own screen — ten divisions across, eight down. 



      

        
        
        
        
        
      

    


    

      

        
Measurements

        

          Taken by the instrument itself over the whole acquisition, not computed
          from the transferred record — so they will differ slightly from the
          statistics under the plot. That difference is real, not a bug.
        

      


      

        
        
        
      


      

    


    


    

      

        
Instrument screen

        

          The oscilloscope's own display, transferred over USB — useful when you
          want the lab report to show what was actually on the bench.
        

      

      

        
        
      

      

    


    

      

        
Command console

        

          Everything exchanged with the instrument. Commands are SCPI over
          USBTMC: CH1:SCALE 5.0E-1 sets channel 1 to 500 mV/div,
          and anything ending in ? is treated as a query.
        

      


      

        
        
        
        
        
        
      


      

    

  


  

    

      The TBS1072B has no USB-serial bridge inside it — it is a native USBTMC
      device — so this page uses the WebUSB API and speaks the
      USBTMC bulk protocol directly. Settings are remembered in this browser
      only; captures are held in memory until you save them.
    

  


  
  
    

      
Nothing in the device chooser?

      

        
      

    


    

      Pressing Connect hands over to Chrome's own device chooser.
      If that list comes up empty, the browser cannot see the instrument yet —
      which is the normal state of affairs until the steps for your system have been
      done once on this computer.
    


    

      
      
      
      
    


    
    

      
Bind the WinUSB driver — once per computer

      

        Windows lets no browser touch a USB instrument unless the generic
        WinUSB driver is bound to it, and it ships nothing for
        test equipment. Until this is done the scope sits in Device Manager under
        Other devices with a yellow warning triangle and problem code 28,
        the drivers for this device are not installed. Because there is no
        driver bound in the first place, binding one displaces nothing — and
        it is reversible.
      

      

        Either route below does the same job. A needs no download,
        which matters on a managed or school machine; B is fewer
        clicks if you can run a downloaded program.
      


      

        

          
A Device Manager

          
Windows already carries the driver. Nothing to download.

          
    
            
  1. Press Win+X and choose Device Manager.
    2. 
            
  2. Find Tektronix TBS 1072B-EDU, most likely under
                Other devices with a warning triangle.
    3. 
            
  3. Right-click it → Update driver.
    4. 
            
  4. Browse my computer for drivers.
    5. 
            
  5. Let me pick from a list of available drivers on my computer.
    6. 
            
  6. Choose the device class Universal Serial Bus devices.
    7. 
            
  7. Manufacturer WinUsb Device, model
                WinUsb Device, then Next.
    8. 
          

        


        

          
B Zadig

          

            A single portable .exe that binds the same driver. Nothing is
            installed: zadig.akeo.ie
          

          
    
            
  1. Download Zadig and run it as Administrator.
    2. 
            
  2. Options → List All Devices.
    3. 
            
  3. Pick Tektronix TBS 1072B-EDU from the dropdown.
    4. 
            
  4. Check the USB ID line reads 0699 0368 — that is
                this instrument.
    5. 
            
  5. Set the target driver, the right-hand box with the green arrow, to
                WinUSB.
    6. 
            
  6. Click Install Driver and wait; it can take a minute.
    7. 
          

        

      


      

        Either way: come back here and press Connect again. The scope
        will be in the chooser.
      


      

        Check that it worked
        
In PowerShell:

        
Get-PnpDevice | Where-Object InstanceId -like '*VID_0699*' |
  Format-List Status, Class, FriendlyName

        

          You want Status: OK and
          Class: USBDevice. Before the bind it reads
          Status: Error with an empty class.
        

      


      

        Undoing it
        

          Device Manager → right-click the scope → Uninstall device,
          tick Delete the driver software for this device, then unplug and replug.
          Windows re-enumerates it bare, and Tektronix's own TekVISA or OpenChoice can
          claim it again.
        

      

    


    
    

      
Nothing to install

      

        macOS has no driver of its own for test instruments, which is exactly what
        WebUSB wants: Chrome claims the interface directly. Plug the scope into the
        rear Device port, press Connect, and choose it from
        the list.
      

      

        If it is still missing, the cause is almost always the instrument rather than
        the Mac — work through the checklist below. The one macOS-specific
        possibility: a VISA runtime installed for other lab software (NI-VISA, TekVISA)
        can claim the instrument first. Quitting that software, or removing the
        runtime, hands it back to the browser.
      

    


    
    

      
Nothing to install

      

        ChromeOS needs no setup whatsoever — no driver, no permissions, no flags.
        Plug the scope into the Chromebook, press Connect, and pick it
        from the chooser. This is the least trouble of any platform, which is worth
        knowing if you are choosing hardware for a class.
      

      

        An empty chooser here points at the instrument's own settings or the cable.
        See the checklist below.
      

    


    
    

      
One udev rule

      

        The kernel needs no driver for this, but the device node it creates belongs to
        root, so Chrome cannot open it as you. Grant access once:
      

      
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="0699", ATTR{idProduct}=="0368", MODE="0666"' \
  | sudo tee /etc/udev/rules.d/99-tektronix.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --attr-match=idVendor=0699

      

        That last line applies the rule to a scope which is already plugged in, by
        replaying a change event against it. Without it you would have to unplug and
        replug before the new permissions took hold.
      

      

        It shows up in the chooser, but connecting fails
        

          Then the rule worked and something else is holding the interface —
          usually the kernel's own usbtmc module, which claims exactly this
          class of device. lsmod | grep usbtmc will say, and
          sudo modprobe -r usbtmc releases the instrument to the browser.
        

      

    


    
    

      
Still nothing? Check the instrument itself

      
    
        
  • 
          The cable belongs in the rear USB Device port, the
          squarish type-B socket. The front port is a host port for flash drives and
          will never work for this.
        
    • 
        
  • 
          On the front panel:
          Utility → Options → USB Device Port → Computer.
          The alternative, Printer, puts the scope in PictBridge mode and
          USBTMC disappears entirely.
        
    • 
        
  • The scope must be switched on and finished booting before you press Connect.
    • 
        
  • 
          Use desktop Chrome or Edge. Firefox and Safari
          do not implement WebUSB, and no browser on iOS does.
        
    • 
        
  • The page has to be on https:// or localhost.
